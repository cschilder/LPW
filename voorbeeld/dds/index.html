DataReaders

Zo ziet het laatste sample eruit als RTPS 2.5-bericht op de draad, precies zoals Eclipse Cyclone DDS het verstuurt (gecontroleerd met een tcpdump van een echte Cyclone-schrijver; daar volgt nog een HEARTBEAT): een RTPS-header, een INFO_TS-submessage met de tijd en een DATA-submessage met de CDR-geserialiseerde struct.


    

    






    

        
Op je eigen computer (Linux/macOS/Windows) met Python en Eclipse Cyclone DDS:

        
pip install cyclonedds
python dds_demo.py sub &     # lezer (TRANSIENT_LOCAL, RELIABLE)
python dds_demo.py pub       # schrijver

        

        
Start de lezer ná de schrijver en je ziet de late-joiner-geschiedenis (TRANSIENT_LOCAL) — precies
        zoals in de simulator. Met tcpdump -i any -X udp portrange 7400-7500 zie je de RTPS-bytes.

        
Twee valkuilen die deze demo zelf tegenkwam: (1) max_blocking_time is in
        nanoseconden — gebruik duration(milliseconds=…); (2) Cyclone levert late joiners maar zoveel
        geschiedenis als DurabilityService.history toestaat (standaard 1). Zonder multicast (bijv. in
        containers of over VPN) zet je discovery op unicast:

        export CYCLONEDDS_URI='<CycloneDDS><Domain><General><AllowMulticast>false</AllowMulticast></General><Discovery><Peers><Peer address="127.0.0.1"/></Peers><ParticipantIndex>auto</ParticipantIndex></Discovery></Domain></CycloneDDS>'

    






    
Hoe werkt DDS?

    

        
DDS (Data Distribution Service, OMG) is publish/subscribe zonder broker: deelnemers vinden
        elkaar via multicast-discovery en sturen data rechtstreeks met het wire-protocol RTPS.
        Gebruikt in ROS 2, defensie, luchtvaart en autonome voertuigen.

        

            
ReliabilityBEST_EFFORT (verlies is verlies) of RELIABLE (HEARTBEAT/ACKNACK, herverzending)

            
DurabilityVOLATILE (alleen nieuwe data) of TRANSIENT_LOCAL (late joiners krijgen geschiedenis)

            
HistoryKEEP_LAST n: hoeveel samples de schrijver bewaart

            
Request vs offeredEen lezer mag nooit méér eisen dan de schrijver biedt (RELIABLE-lezer + BEST_EFFORT-schrijver = geen match)
